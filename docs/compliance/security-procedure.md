# נוהל אבטחת מידע — Fitura+

> **טיוטה לבדיקה.** נוהל לפי תקנה 4 לתקנות הגנת הפרטיות (אבטחת מידע), התשע״ז-2017, ברמת אבטחה בינונית. יש לאשר את הנוהל על ידי בעל המאגר, להביא אותו לידיעת כל בעלי ההרשאה, ולעדכן אותו לפחות פעם בשנה.
>
> עודכן: 2026-11-28

## 1. אחריות
- ממונה אבטחת מידע: `[למילוי]` — אחראי לנוהל, לבקרות ולטיפול באירועים.
- כל בעל הרשאה (מנהל מערכת, מפתח עם גישה לשרת) מאשר בכתב שקרא את הנוהל ומתחייב לסודיות.

## 2. בקרות שמומשו במערכת

| תחום | מה קיים | איפה |
|---|---|---|
| הזדהות משתמשים | סיסמה ≥10 תווים, גיבוב scrypt עם salt, השוואה בזמן קבוע | `src/lib/security.ts` |
| סשנים | טוקן אקראי 256 ביט, שמור במסד רק כגיבוב, עוגייה HttpOnly + Secure + SameSite, תוקף 7 ימים; איפוס סיסמה מבטל את כל הסשנים | `src/lib/auth.ts` |
| הזדהות מנהלים | סיסמה ≥14 תווים, **MFA חובה** (TOTP עם הגנה מפני שימוש חוזר + קודי שחזור), נעילה אחרי 5 ניסיונות, ניתוק אחרי 30 דק׳ ללא פעילות / 8 שעות, אימות חוזר לפעולות רגישות | `src/lib/admin/auth.ts` |
| הפרדת ממשק ניהול | הקונסולה זמינה רק בדומיין `ADMIN_HOST`, עוגייה `__Host-`, CSP קשיח, noindex | `src/proxy.ts` |
| הרשאות | בדיקת בעלות בצד השרת בכל בקשה; מאמן רואה רק מתאמנים שאישרו; RBAC למנהלים | `src/app/api/[...path]/route.ts`, `src/lib/admin/rbac.ts` |
| CSRF | בדיקת Origin בכל בקשה משנה; כותרת ייעודית לקונסולה | `src/lib/request-origin.ts` |
| הגבלת קצב | מונים במסד לכל משתמש, כתובת דוא״ל ובאופן גלובלי | `rateLimit` |
| הצפנה בתעבורה | HTTPS בלבד, HSTS, הפניה מ-HTTP | `src/proxy.ts`, Caddy / Hostinger |
| הצפנה במנוחה | תמונות התקדמות, סודות TOTP ומפתחות AI מוצפנים ב-AES-256-GCM עם `ADMIN_ENCRYPTION_KEY` | `src/lib/admin/crypto.ts` |
| תמונות | עיבוד מחדש ל-JPEG (מסיר מטא-דאטה כולל מיקום GPS), הגבלת גודל ופיקסלים | `src/lib/bodyweight.ts` |
| יומני ביקורת | יומן פעולות משתמשים; יומן מנהלים append-only עם הסתרת סודות, כולל צפייה ברשימות ובפרופילים וניסיונות גישה שנדחו | `src/lib/admin/audit.ts` |
| גיבוי | גיבוי עקבי (VACUUM INTO) לפני כל פריסה ובאופן מתוזמן, 14 עותקים | `src/lib/jobs.ts` |
| Webhooks | אימות חתימה, אחזור מצב קנוני מהספק, מניעת עיבוד כפול | `src/app/api/webhooks/` |
| סודות בקוד | אין סודות ב-git; `.env*` מוחרג | `.gitignore` |

## 3. פעולות ארגוניות נדרשות

- [ ] **מפתח ההצפנה:** לגבות את `ADMIN_ENCRYPTION_KEY` (ב-Hostinger: `~/fitura-data/.admin-encryption-key`) **במקום נפרד** מגיבויי המסד. בלי המפתח לא ניתן לקרוא את התמונות.
- [ ] **הצפנת גיבויים:** הגיבויים (`~/fitura-data/backups`) אינם מוצפנים כקובץ. להעתיק גיבוי מחוץ לשרת רק מוצפן.
- [ ] **הצפנת דיסק:** לבדוק אם Hostinger מספקת הצפנת דיסק לשרת.
- [ ] **ניהול הרשאות:** רשימה מעודכנת של בעלי גישה ל-Hostinger, ל-SSH, ל-GitHub ולקונסולת הניהול; MFA בכולם; ביטול גישה מיידי בסיום תפקיד.
- [ ] **סקירת יומנים:** ממונה האבטחה עובר על יומן המנהלים לפחות פעם בחודש (ניסיונות שנדחו, ייצואים, מחיקות).
- [ ] **עדכוני תוכנה:** `npm audit` ועדכון תלויות לפחות פעם בחודש, ומיד בפרצה קריטית.
- [ ] **מבדק חדירות / סקר סיכונים:** לפחות פעם ב-18 חודשים (רמה בינונית).
- [ ] **הדרכה:** הדרכת אבטחה לבעלי הרשאה עם קבלת התפקיד ולפחות פעם בשנתיים.
- [ ] **ספקים:** הסכם עיבוד נתונים (DPA) עם כל ספק ברשימה ב-`records-of-processing.md`.
- [ ] **שחזור:** לבצע ולתעד שחזור ניסיוני מגיבוי לפחות פעם ברבעון.
